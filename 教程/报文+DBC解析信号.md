# 报文 + DBC 解析信号（简明教程）

以 A05大陆 的 `GW_530` 报文、`IP_EngineOffTime`（发动机停机时间）信号为例。

## 例子

一帧报文（CANalyzer Trace 里看到的）：

```
ID = 530    DLC = 8    数据 = FF FF 00 00 18 0C 24 FF
```

DBC 里的定义：

```
BO_ 1328 GW_530: 8
 SG_ IP_EngineOffTime : 7|16@0+ (1,0) [0|65535] "s"
 SG_ IP_TotalOdometer : 23|24@0+ (0.1,0) [0|999999] "Km"
VAL_ 1328 IP_EngineOffTime 0 "0-65533s" 65534 "65534 or >65534" 65535 "invalid" ;
```

## 六步解析

### 1. 用 ID 找报文
报文 ID 是十六进制，DBC 里写十进制：`0x530 = 1328`，对应 `BO_ 1328 GW_530`。

### 2. 给字节和位编号
```
数据：  FF    FF    00    00    18    0C    24    FF
字节： Byte0 Byte1 Byte2 Byte3 Byte4 Byte5 Byte6 Byte7
```
位号 = 字节号 × 8 + 字节内位号（0~7）：

| 字节 | 位号（高 → 低） |
|---|---|
| Byte0 | 7 … 0 |
| Byte1 | 15 … 8 |
| Byte2 | 23 … 16 |
| Byte3 | 31 … 24 |
| Byte4 | 39 … 32 |

### 3. 读懂信号定义
`7|16@0+ (1,0) [0|65535] "s"`

| 写法 | 含义 |
|---|---|
| `7` | 起始位 7 |
| `16` | 长度 16 位 |
| `@0` | Motorola 格式（高字节在前）；`@1` 是 Intel（低字节在前） |
| `+` | 无符号；`-` 是有符号（补码） |
| `(1,0)` | 系数 1，偏移 0 |
| `[0\|65535]` | 范围 |
| `"s"` | 单位 |

### 4. 找到占哪几个字节，拼成原始值
Motorola：起始位是最高位，往低位数，一个字节数完就跳到**下一个字节的 bit7** 继续。

起始位 7 = Byte0 最高位，16 位 → **Byte0、Byte1**：
```
FF FF → 0xFFFF → 65535
```

### 5. 换算物理值
**物理值 = 原始值 × 系数 + 偏移**
```
65535 × 1 + 0 = 65535 s
```

### 6. 查值描述（VAL_）
65535 = **"invalid"**。

**结论：IP_EngineOffTime 发的是无效值，不是停机了 65535 秒。**

## 验证：同一帧算里程
`IP_TotalOdometer : 23|24@0+ (0.1,0)`

- 起始位 23 = Byte2 最高位，24 位 → **Byte2、Byte3、Byte4** = `00 00 18`
- 原始值 0x000018 = 24
- 物理值 24 × 0.1 = **2.4 Km**（与 CANalyzer 展开显示一致）

## 一句话
**ID 找报文 → 起始位 + 长度定位字节 → 按字节序拼原始值 → × 系数 + 偏移 → 查 VAL_ 特殊值。**
